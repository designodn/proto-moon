# Архитектура proto-moon: карта слоёв и папок

Документ отвечает на один вопрос: **из чего состоит такой проект и по каким швам
он разбирается**, если другой бизнес-юнит захочет завести себе такой же.

Не пересказ README (тот про «как запустить») и не спека контента (это
`docs/feeds-spec.md`). Здесь — слои, папки, зависимости между ними и цена переноса.

**Как читать:**
- быстрый ответ «что где лежит» — раздел 3 (карта по папкам);
- «что забрать в новый проект» — раздел 9 (швы + чек-лист);
- «почему нельзя просто переложить папки» — раздел 10 (сцепление, цифры).

Все цифры замерены по репозиторию на дату документа; способ замера указан там, где
он неочевиден.

---

## 1. Что это за проект

Статический HTML-прототип мобильного соцсетевого приложения. Ни сборки, ни
фреймворка, ни рантайма: 44 HTML-страницы, CSS-компоненты, ванильный JS, статика.
`package.json` держит ровно одну зависимость (`sharp`) — и та нужна
**только скриптам сбора контента**, не странице.

Из этого следует главное архитектурное свойство: **страница = файл**, а структура
папок == публичные URL. Всё остальное (роуты сервера, «контейнер» прототипа, пути в
скриптах) надстроено поверх этого факта.

---

## 2. Три слоя

Слои существуют логически, но физически лежат **вперемешку в корне репозитория** —
отдельных директорий `ds/` и `app/` нет.

| Слой | Что это | Переносимость между БЮ |
|---|---|---|
| **ДС** | Токены, шрифты, ~80 CSS-компонентов, 975 иконок, витрина `preview.html` | Берётся **как есть** |
| **Приложение** | 44 страницы-экрана, 4 папки-прототипа, контент (`data/`, `assets/`) | **Пишется заново** под свой БЮ |
| **Инфра + правила** | Сервер, деплой, скрипты сбора, git-хук, `.claude/` агенты и правила | Берётся **с правкой конфигов** |

Граница ДС/приложение проходит не по папкам, а по вопросу «есть ли здесь знание о
конкретном продукте». `components/uni-card.css` — ДС. `components/vvz-card.css`,
`components/nv-navbar.css` — уже продуктовое, хоть и лежит в той же папке.

## 4. Как устроен ДС

**Точка входа одна — `index.css`.** Страница подключает её (`<link rel="stylesheet"
href="index.css">`), дальше 71 `@import` тянут всё остальное в фиксированном порядке:
`tokens.css` → `fonts.css` → `animations.css` → примитивы → производные компоненты →
`type-scale.css`. У части импортов кэш-бастер (`?v=20260731-2`) — способ пробить
кэш прототипа без переименования файла.

34 из 44 страниц подключают `index.css`; часть дополнительно тянет отдельные
`components/*.css` (то, чего нет в общем входе, или NV-оверрайды).

**Токены (`tokens.css`).** 509 переменных, разложенных по секциям:

| Секция | Селектор | Содержимое |
|---|---|---|
| Базовые | `:root` | `--font-family`, спейсинг (сетка 4px), радиусы, `--static-*` |
| Типографика | `.ds-*` | 12 хелпер-классов: `ds-display-xl/m`, `ds-title-xl/l/m/s`, `ds-body-l/m`, `ds-caption-m/-accent/s/-accent` |
| Светлая тема | `:root.__ui-theme_enabled.__ui-theme_light` | `--dynamic-*` |
| Тёмная тема | `:root.__ui-theme_enabled.__ui-theme_dark` | `--dynamic-*` |
| Альт-тема | `:root.theme-cocktail…` (light + dark) | Переопределяет `--dynamic-*` |

Тема переключается **классами на `<html>`** — рантайма нет:
`<html class="__ui-theme_enabled __ui-theme_light">`. `theme-cocktail` вешается
дополнительно к light/dark — это готовый шов для «второго бренда» поверх той же
разметки. Шрифт переопределяется тем же приёмом: `.__font-roboto` на `<html>`
перебивает `--font-family` для всего поддерева (так работает `lenta-q3.html`).

**Иконки.** 975 SVG в `assets/icons/` плоским списком. Разметка их не знает: 32
семантических слота в `icon.css` мапят класс на файл —

```css
.icon.__slot-back { --icon-src: url('../assets/icons/arrow_left_24.svg'); }
```

Поэтому `<span class="icon __size-24 __slot-back">` не зависит от имени файла, и
NV-тема переопределяет глиф, не трогая страницы (`components/nv-navbar.css`).

**Витрина.** `preview.html` — единственная страница, показывающая ДС как ДС:
компоненты, состояния, размеры. Доступна по `/preview`; `index.html` — метаредирект
на неё, так что на GitHub Pages корень сайта = витрина ДС.

## 5. Как устроено приложение

**Страница = экран.** Один HTML — один экран приложения, переходы — обычные ссылки
и `location.href`. Анимацию перехода и историю централизует
`components/screen-transition.js`; кнопка «назад» — DS-иконка + класс
`nav-bar__back`, не свой `history.back()` (см. CLAUDE.md §1).

**Прототип = папка.** Ключевое решение. Экспериментальный сценарий не ветвится в
git и не прячется за флагом — он **копируется в свою папку**: `activity-lenta/`,
`events-lenta/`, `new-vision/`, `koleso/`. Плюс: прототипы живут одновременно, у
каждого свой URL, ДС общий. Минус: дублирование страниц (`events-lenta/` — копия
`activity-lenta/`) и необходимость технически удерживать границу папки.

Границу удерживают два механизма:

1. **`<base href="../">`** на страницах `activity-lenta/` и `events-lenta/` — все
   относительные пути (включая `location.href` из `tab-bar.js`) резолвятся от
   **корня репозитория**, а не от папки страницы. Это позволяет прототипу
   переиспользовать общие ассеты и страницы, но ломает «локальность» ссылок.
2. **`components/proto-contain.js`** — «контейнер»: перехватывает клики на
   `window`-capture и гасит любую навигацию за пределы папки текущей страницы.
   Папка вычисляется из `location.pathname` (`var DIR = location.pathname.replace(/[^/]*$/, '')`)
   — путь монтирования не захардкожен. Исключения:
   - `TAB_ALLOW_OUT = { message, clip, menu }` — слоты таб-бара, которым **разрешён**
     выход в общие разделы приложения;
   - `TAB_ROUTES` — дубль карты маршрутов из `tab-bar.js` (нужен, чтобы понять цель
     кнопки без `data-href`);
   - `LEAKY` — селекторы узлов, чьи inline-обработчики уводят наружу без `href`.

Отсюда типовая поломка «таб-бар не навигирует»: маршрут есть, но слот не внесён в
`TAB_ALLOW_OUT` (CLAUDE.md §2).

**New Vision — образец правильной надстройки.** NV не форкает ДС, а наслаивается:

```
new-vision/new-vision.css
  ├─ @import '../index.css'            ← общая ДС целиком
  ├─ @import '../components/nv-*.css'  ← оверрайды общих компонентов
  ├─ @import './components/nv-*.css'   ← новые NV-компоненты
  ├─ @import './feeds/nv-feed*.css'    ← дивергентные фид-карточки
  └─ @import './nv-fonts.css'          ← шрифтовая карта, последней (каскад)
```

Форкается **только расходящееся**. Плюс NV «протекает» на общие страницы: если URL
содержит `?nv=1` или путь начинается с `/new-vision/`,
`components/screen-transition.js` динамически подмешивает `nv-fonts.css` и
`nv-navbar.css` и дописывает `?nv=1` ко всем локальным переходам. Для другого БЮ это
и есть шаблон «своя тема поверх общего ДС».

## 6. Пайплайн контента

Контент не пишется в HTML руками — он **приезжает из Google-таблицы** (один
spreadsheet, ID в `docs/feeds-spec.md` и `.claude/skills/fetch-all/SKILL.md`) и
запекается в репозиторий локально автором. Сервер в этом не участвует вообще.

```
Google Sheets (лист = раздел, gviz CSV)
        │
        ├─ sheet-cache.mjs  → хэш CSV + хэш кода рендера; лист не менялся → шаг пропущен
        │
   scripts/fetch-<раздел>.mjs
        │
        ├─ media-cache.mjs  → качает чужие CDN-картинки локально, sharp: ≤1600px, webp q80,
        │                     манифест data/<feed>-media.json (URL → файл + хэш, prune сирот)
        │
        └─ два вида выхода:
             (а) data/*.json  (+ data/*.js — зеркало для браузера)
             (б) блок, запечённый прямо в HTML между
                 <!-- FEED:START … --> и <!-- FEED:END -->
```

**Выход (а) — данные файлом.** 27 JSON + 4 JS в `data/`. JS-зеркала — просто
`window.DS_PEOPLE_DATA = [...]`, подключаются тегом (`<script src="data/people.js">`)
и читаются `components/people-data.js` / `user-data.js`; на `data/people.js`
ссылаются 34 страницы. Контракт карточек — `data/q3-feed.schema.json`.

**Выход (б) — запечённый HTML.** Маркеры `FEED:START` / `FEED:END` есть в 6
страницах: `lenta-q3.html`, `tribune.html`, `marathon.html`, `new-vision/lenta.html`,
`activity-lenta/lenta.html`, `events-lenta/lenta.html`. Всё между маркерами
перетирается следующим прогоном — правки вносятся в лист или в шаблон внутри скрипта.

**Один генератор на четыре ленты.** `scripts/fetch-q3.mjs` обслуживает Q3, Трибуну,
Activity и События — различие сидит в объекте `FEEDS` и включается флагом:

| Флаг | Лист | JSON | Целевой HTML | Медиа |
|---|---|---|---|---|
| — | «Q3-посты» | `data/q3-feed.json` | `lenta-q3.html` | `assets/q3/` |
| `--tribune` | «Трибуна» | `data/tribune-feed.json` | `tribune.html` | `assets/tribune/` |
| `--activity` | «lenta-activity» | `data/activity-feed.json` | `activity-lenta/lenta.html` | `assets/activity/` |
| `--events` | тот же лист | `data/events-feed.json` | `events-lenta/lenta.html` | `assets/activity/` |

Дополнительные флаги: `--offline` (реген из уже скачанного JSON, без сети),
`--force` (игнорировать инкрементальный пропуск), `--check`.

**Оркестратор.** `scripts/fetch-all.mjs` — массив `STEPS` из 14 шагов в жёстком
порядке: `fetch-people` первым (остальные резолвят людей по id) → ленты → профиль →
клипы → активности → `verify-activity-text` → сториз → марафон → подарки →
`wire-vvz` (доразметка `data-person` на ВВЗ-карточках). Падение шага не останавливает
остальные, в конце — сводка. Без `sharp` скрипт отказывается стартовать (иначе в репо
уедут несжатые оригиналы); обход — `ALLOW_NO_SHARP=1`. Обёртка для агента —
скилл `.claude/skills/fetch-all/`.

## 7. Инфра и деплой

**Сервер (`server.mjs`).** Голый `node:http`, без зависимостей. Делает четыре вещи:

- отдаёт статику из корня (защита от `../`, MIME-таблица, `Cache-Control: no-cache`);
- редиректит «красивые» пути: `/nv` → `/new-vision/lenta.html`, `/activity` →
  `/activity-lenta/view.html`, `/events` → `/events-lenta/view.html`, `/q3` →
  `/q3-view.html`, `/preview` → `/preview.html`. **Именно редирект (302), а не отдача
  чужого контента** — иначе относительные пути внутри страницы резолвились бы от
  красивого URL и всё бы поехало;
- отдаёт инлайн-лендинг со списком прототипов на `/`;
- `/healthz` и `/robots.txt` + заголовок `X-Robots-Tag: noindex, nofollow` на всё
  (прототип не должен попадать в поиск).

**Два независимых канала публикации:**

| Канал | Что делает | Следствие |
|---|---|---|
| GitHub Pages (`deploy-pages.yml`) | На каждый push в `main` заливает **корень репо как есть** (`path: '.'`) | Структура папок == публичные URL. Красивых роутов нет, корень = `index.html` → редирект на витрину ДС |
| Docker / Yandex (`Dockerfile`, `docker-compose.yml`, `deploy.sh`, `setup-yandex.sh`) | `node:22-slim`, `npm start` → `server.mjs`, `PORT` из окружения | Есть красивые роуты и лендинг |
| SourceCraft (`mirror-sourcecraft.yml`) | Зеркалит все ветки и теги на каждый push | Резервная копия |

Расхождение поведения корня между каналами (`/` = лендинг на сервере, `/` = витрина
ДС на Pages) — следствие того, что Pages не умеет роутинг, а не ошибка.

## 8. Слой правил и агентов

Для другого БЮ это часть продукта, а не случайный мусор в репозитории: именно эти
файлы удерживают качество макетов, когда их собирает агент.

| Артефакт | Роль |
|---|---|
| `CLAUDE.md` | Обязательные правила сборки: компоненты только из ДС, значения только из токенов, кнопка «назад» через `__slot-back`, таб-бар в подпапках, порядок проверки перед коммитом |
| `SESSION-INSIGHTS.md` | 28 КБ накопленных граблей по конкретным DS-компонентам |
| `docs/feeds-spec.md` | Контракт лент: типы карточек, поля, колонки листа, реген |
| `.claude/agents/macket-rules-checker.md` | Read-only ревьюер: grep-first сверяет дифф с правилами, вердикт PASS/FAIL. Гоняется **один раз перед коммитом** |
| `.claude/agents/macket-insights-curator.md` | Переносит устойчивые находки из инсайтов в правила (по крону) |
| `.claude/agents/screenshot-testing.md` | Прогон интерактива в браузере (Playwright + Chromium в окружении) |
| `.claude/skills/fetch-all/` | Скилл-обёртка над пайплайном контента (+ `sheets.md` с описанием листов) |
| `.githooks/pre-commit` → `scripts/nbsp.mjs` | Детерминированная расстановка неразрывных пробелов в изменённых `.html`: правит только видимый текст, не трогает теги/атрибуты/`<script>`/`<style>`/`<pre>`/`<code>`. Хук включается SessionStart-хуком из `.claude/settings.json` (`git config core.hooksPath .githooks`) |

Принцип, который стоит скопировать целиком: **типографика и проверка правил —
детерминированные скрипты и read-only агент, а не дисциплина человека.**

## 9. Швы переносимости: как завести такой проект для нового БЮ

### Что берётся как есть

- `tokens.css` (структура секций и имена переменных; значения — под бренд),
  `index.css`, `animations.css`;
- примитивы `components/*.css`: `uni-card`, `uni-cell`, `button*`, `avatar`, `icon`,
  `badge`, `media`, `header`, `tabbar`, `tabs`, `tab`, `chips`,
  `divider`, `text-input`, `content`, `island`, `phone-frame`, `app-shell`;
- поведенческий JS: `screen-transition.js`, `tab-bar.js`, `masonry.js`,
  `smart-crop.js`, `image-skeleton.js`, `back-trap.js`;
- `assets/icons/` + маппинг `__slot-*` в `icon.css`;
- `preview.html` как каркас витрины (содержимое — под свой набор компонентов);
- `scripts/lib/`: `media-cache.mjs`, `sheet-cache.mjs`;
- `scripts/nbsp.mjs` + `.githooks/pre-commit`;
- `CLAUDE.md`, `.claude/agents/macket-rules-checker.md`, `.github/workflows/deploy-pages.yml`.

### Что подменяется

| Что | Чем |
|---|---|
| Палитра и типографика в `tokens.css` | Своими значениями; имена переменных лучше сохранить |
| `fonts.css` + `fonts/` | Своим шрифтом (`--font-family` в `:root`) |
| Список `@import` в `index.css` | Вычистить продуктовые компоненты чужого БЮ |
| `PROTOTYPES` и лендинг в `server.mjs` | Своими роутами и списком прототипов |
| `SPREADSHEET_ID` и gid'ы в `scripts/fetch-*.mjs` | Своей таблицей |
| `TAB_ROUTES` / `TAB_ALLOW_OUT` в `proto-contain.js` и `ROUTES` в `tab-bar.js` | Своей навигацией |
| `.sourcecraft/`, `deploy.sh`, `setup-yandex.sh` | Своим хостингом (или выкинуть, оставив Pages) |

### Что пишется заново

- все страницы-экраны и папки-прототипы;
- продуктовые компоненты (аналоги `feed-*`, `vvz-card`, `clip-*`, `gift-card`);
- `data/*` и схемы карточек, `docs/<свой>-spec.md`;
- `assets/` кроме `icons/`;
- шаблоны рендера внутри `fetch-*.mjs` (каркас скрипта — sheet-cache → media-cache →
  запекание между маркерами — переиспользуется).

### Чек-лист запуска

1. Снять ДС: `tokens.css`, `index.css`, `fonts*`, `animations.css`, `components/`
   (только примитивы + поведенческий JS), `assets/icons/`, `preview.html`.
2. Перекрасить токены под бренд, подменить шрифт, прогнать `preview.html` глазами.
3. Почистить `index.css` от импортов, которые не переехали.
4. Поднять `server.mjs`, переписать `PROTOTYPES` и лендинг; включить
   `deploy-pages.yml` (Pages публикует корень как есть — заранее решите, что лежит
   в корне и что показывает `index.html`).
5. Завести таблицу-источник, описать листы в `docs/*-spec.md`, склонировать один
   `fetch-*.mjs` под свой первый лист, подключить `scripts/lib/` без изменений.
6. Перенести `CLAUDE.md` + `macket-rules-checker` + `.githooks/pre-commit` **до**
   того, как начнут собираться первые экраны, — иначе правила будут догоняющими.
7. Определить конвенцию прототипов: одна папка = один прототип, `proto-contain.js`
   с прописанными `TAB_ROUTES`/`TAB_ALLOW_OUT`.
8. Собрать первый экран и только потом остальные — на первом видно, чего не хватает
   в ДС.

## 10. Сцепление и цена реорганизации (предложение, не решение)

Реорганизацию **не делали**; раздел нужен, чтобы посчитать её заранее и понять,
что именно держит текущую структуру.

### Что сцепляет слои сейчас

| Механизм | Замер / место | Почему держит |
|---|---|---|
| Только относительные ссылки | Корневых (`/…`) ссылок в HTML — **0** | Любой сдвиг файла по дереву меняет все пути в нём |
| Ссылки на `components/` | **488** вхождений (html/css/js/mjs/json) | Перенос ДС = массовая замена префикса |
| Ссылки на `assets/` | **1684** вхождения | Перенос медиа — самый дорогой шаг |
| Ссылки на `tokens.css` | **17** | Дёшево |
| `<base href="../">` | 8 страниц: `activity-lenta/*`, `events-lenta/*` (+ `components/today-widgets.partial.html`) | Пути резолвятся от корня репо; смена глубины дерева ломает семантику разом |
| `proto-contain.js` | 4 страницы; `DIR` из `location.pathname` | Граница прототипа == граница папки. Переезд папки меняет, что считается «своим» |
| Пути в скриптах | `resolve(ROOT, 'lenta-q3.html')`, `resolve(ROOT, 'data/people.json')`, `mediaDir: 'assets/activity'` и т.п. в `fetch-*.mjs` | Скрипты надо править синхронно с переездом |
| Роуты сервера | `PROTOTYPES` в `server.mjs` | Правится тривиально, но обязателен |
| GitHub Pages | `path: '.'` — публикуется корень как есть | **Структура папок == публичные URL**: переезд ломает все внешние ссылки на прототипы |

### Целевая структура (если делать)

```
ds/     tokens.css, index.css, fonts.css, fonts/, animations.css,
        components/ (примитивы), assets/icons/, preview.html
app/    страницы-экраны, activity-lenta/, events-lenta/, new-vision/, koleso/,
        data/, assets/ (кроме icons)
```

### Оценка по шагам

| Шаг | Объём правок | Риск | Ломает ли публичные URL |
|---|---|---|---|
| **A. Вынести ДС в `ds/`** | ~488 ссылок на `components/`, 17 на `tokens.css`, +пути внутри `index.css` и `icon.css` | Низкий: замена префикса механическая, проверяется прогоном `preview.html` и любой ленты | **Нет** — страницы остаются на месте |
| **B. Вынести приложение в `app/`** | 1684 ссылки на `assets/`, семантика `<base href>` на 8 страницах, `DIR` в `proto-contain.js`, пути в 10+ `fetch-*.mjs`, `PROTOTYPES` в `server.mjs` | Высокий: правки в четырёх независимых местах (разметка, JS-логика границ, генераторы, роутинг), регрессии видны только в браузере | **Да** — меняются все URL прототипов на Pages |

Практический вывод: **A и B — разные по цене задачи, и их не нужно делать вместе.**
Шаг A даёт основную ценность для упаковки в скилл (ДС становится физически
отделимым и его можно копировать одной папкой), стоит порядка пятисот механических
замен и не трогает ни один публичный адрес. Шаг B — вопрос вкуса к чистоте корня,
стоит втрое дороже и ломает ссылки, которыми уже пользуются.

Если делать A, минимальный порядок:

1. Перенести файлы, обновить внутренние пути ДС (`index.css` → `./tokens.css`,
   `icon.css` → `../assets/icons/…` меняет глубину).
2. Массовая замена `components/` → `ds/components/`, `tokens.css` → `ds/tokens.css`
   в HTML/CSS/JS. Отдельно проверить страницы с `<base href="../">` — там путь
   считается от корня репо, а не от папки страницы.
3. Проверить `new-vision/new-vision.css` (`@import '../index.css'`) и
   `koleso/*.html` (`href="../index.css"`) — они ссылаются на вход ДС вручную.
4. Прогнать `preview.html`, по одной странице каждого прототипа и таб-бар в
   `activity-lenta/` реальным кликом в браузере.
5. Обновить `CLAUDE.md` (пути в примерах) и `macket-rules-checker`.
